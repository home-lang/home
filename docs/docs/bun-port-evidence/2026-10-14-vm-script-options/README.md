# Native script option parsing and empty cached data

This checkpoint contributes to #66 and #891. The broader VM lifetime acceptance in #885 remains open.

Construction and execution now parse independent option sets. Construction snapshots filename, lineOffset, columnOffset, cachedData, produceCachedData and importModuleDynamically before validation, using ordinary property reads and a scoped GC-traced buffer. It ignores context metadata, timeout and microtaskMode. Execution ignores construction fields and reads/validates timeout before snapshotting displayErrors and breakOnSigint. Arrays/functions and their Proxy wrappers are rejected as option objects. Virtual Proxy values work without has-property operations, and later getter exceptions preserve their identity.

Execution timeouts use the positive uint32 range. Signed int32 source offsets are validated numerically, so negative zero and integer values loaded from double-backed JS arrays are accepted. Raw ArrayBuffer cachedData is rejected; Buffer, typed-array and DataView inputs retain their existing cache path. Empty supplied caches are distinguished from omitted cachedData and rejected because they cannot contain a bytecode header. The marker is a constructor-local parsing output; the accepted native class header/layout and ABI checks remain unchanged. Fresh cache data can still be produced after empty input is rejected.
